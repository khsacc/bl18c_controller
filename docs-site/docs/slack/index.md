# Slack

[Experimental Scheduler](../apps/exp-scheduler/index.md) の実行状況を Slack で受け取ることができます。

## 通知

シーケンスの完了、停止条件による終了、エラーによる停止のときに、指定したチャンネルへメッセージを投稿します。シーケンスの開始時や、ユーザーが **Stop** を押したときには投稿しません。通知を有効にするには、Experimental Scheduler のツールバーにある **Notify on Slack** にチェックを入れます。Slack の設定がされていない場合、このチェックボックスは選択できません。

## スラッシュコマンド一覧

Slack Bot（Auto-18C）とのダイレクトメッセージで、以下のコマンドを送信することで実験の状況を把握することができます。

| コマンド | 内容 |
| --- | --- |
| `/bl18c`、`/bl18c status` | シーケンスの実行状態と現在のステップを表示します。 |
| `/bl18c progress` | 完了したステップ数、現在のループ、最新の進捗メッセージを表示します。 |
| `/bl18c steps`、`/bl18c sequence` | 実行中または最後のシーケンスのステップ一覧を表示します。 |
| `/bl18c lakeshore` | LakeShore 335 の温度、設定温度、昇温速度、ヒーター範囲を表示します。 |
| `/bl18c pace5000` | PACE5000 の現在圧力、目標圧力、圧力変化速度を表示します。 |
| `/bl18c sample` | 試料の温度、ガス圧、直近のルビー圧力測定値を表示します。 |
| `/bl18c screenshot` | 表示中の Experimental Scheduler ウィンドウ全体の画像を DM に送ります。 |
| `/bl18c screenshots` | Scheduler ウィンドウ全体の画像と、Camera2 の最新の静止画を同じ DM に送ります。 |
| `/bl18c screenshot [steps\|microscope\|pt\|xrd\|ruby]` | 指定した表示中のパネルの画像を DM に送ります（ステップ表、顕微鏡、圧力・温度、XRD、ルビー圧力）。 |
| `/bl18c xrd rawimg` | 直近の XRD 生画像を TIFF 形式で DM に送ります。 |
| `/bl18c camera` | ビームラインのネットワークカメラから新しく取得した静止画（JPEG）を DM に送ります。 |
| `/bl18c help` | コマンドの使い方を表示します。 |

### ネットワークカメラの画像

`/bl18c screenshots` は、`/bl18c screenshot` と `/bl18c camera` の両方をまとめて要求します。引数は不要です。受付結果はそれぞれ表示され、2枚の画像は個別に送信されます。到着順は一定ではありません。一方が利用できない場合や処理中の場合でも、もう一方は要求します。Scheduler ウィンドウは表示中である必要があり、Camera2 には下記の認証設定と要求間隔の制限が適用されます。

`/bl18c camera` は、[カメラの表示ページ](http://130.87.177.70/CgiStart?page=Single&Language=1)と同じカメラから、640×480 の静止画を取得します。撮影方向やカメラの設定は変更しません。Experimental Scheduler ウィンドウが閉じていても、ランチャーと Slack のコマンド応答が動作していれば利用できます。

このカメラには認証が必要です。ビームライン PC の Windows の「環境変数」で、ユーザー環境変数 `BL18C_CAMERA2_USERNAME` と `BL18C_CAMERA2_PASSWORD` に静止画の閲覧権限があるカメラのユーザー名とパスワードを設定し、アプリケーションを再起動してください。Slack のトークンとは別の認証情報です。コマンドにはパスワードを入力しません。

画像取得と Slack への送信は専用のバックグラウンド処理で行います。同時に受け付ける要求は 1 件で、要求間隔は 3 秒以上です。認証や通信に失敗した場合は要求元の DM にエラーを返し、実験シーケンスには影響しません。画像取得の通信タイムアウトは 5 秒、画像サイズの上限は 5 MiB です。

ビームライン PC からカメラへの直接接続が必要です。カメラへの通信にはプロキシを使用しません。Slack の通信設定は従来どおりです。画像送信には既存のスクリーンショットと同じ `files:write` 権限を使用します。

トークンや通知先チャンネルの設定方法は [Slack notifications](../settings/slack.md) を参照してください。

:::info
Slack との通信に失敗しても、実行中のシーケンスには影響しません。また、`--debug` モードでは通知の送信もスラッシュコマンドへの応答も行いません。
:::
